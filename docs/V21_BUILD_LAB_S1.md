# 《薪水勇者》V21：六人羈絆研究室 S1 規則驗證原型

日期：2026-11-11

**狀態：純函式規則與自動化測試；尚未接到遊戲主畫面、尚未替換 V19 單主角實戰。** 不能宣稱六人羈絆已在正式版可玩。保留原有薪資、怪物動畫、裝備、存檔與戰鬥計算。

## 核心定案方向

1. **六名實戰隊員**，主角擔任棋盤外獨立指揮官。不強迫玩家在手機畫面擺放 TFT 棋盤，配隊改用清楚的六張角色卡與一鍵預設。
2. **基礎羈絆**：每個職業有兩個天然標籤。兩名啟動初級、四名啟動進階；不是每個羈絆都必須硬湊六名。
3. **羈絆移植**：指定隊員多取得一個本來沒有的標籤。研究室原型限制一隊最多 **兩次移植**；不能在同一人重複堆同種羈絆，也不可讓一名角色被計算兩次。
4. **羈絆鍊成**：兩種羈絆均達到至少兩人時，選擇融合成一種特殊規則，**犧牲來源羈絆原有的被動效果**。初版只能啟動一種融合，防止無代價全拿。
5. **技能事件連鎖**：普通攻擊、追擊、召喚打擊、治療、護盾承傷、毒傷與主角指揮充能彼此影響。衍生攻擊不能再無限衍生同樣效果；每輪最多處理 28 事件。
6. **裝備技能變異**：五件原型裝備實際改變技能輸出、護盾、毒傷與召喚事件，而不只是增加人物數值。
7. **敵人機制克制**：五種敵人原型，有毒傷淨化、破盾、召喚抵抗與高壓長線戰。原型能用固定 random seed 進行公平對照研究。

## 已建立的原型

- `v19/v21-build-lab.mjs`：純資料與自動戰鬥模擬，匯出 `analyzeLabBuild`、`simulateLabBattle`、`compareLabBuilds`。
- `v19/v21-build-lab.test.mjs`：原型資料、配方合法性、跨職業移植、同種子重現、裝備和融合是否有實際效果、敵人克制、指揮官差異、事件佇列上限、存檔不變更。
- `.github/workflows/v19-gameplay-ci.yml`：把上述原型加入現有 Node 遊戲測試，讓未來更動有回歸保護。

### 六個可測試的融合方案

| 來源羈絆 | 融合名稱 | 預期機制 |
|---|---|---|
| 社畜＋機械 | 永動加班 | 每三次攻擊觸發機械追擊 |
| 夜班＋暗影 | 午夜死契 | 毒傷獲得第二段暗影傷害 |
| 守護＋奧術 | 不屈迴路 | 護盾承傷觸發奧術反擊 |
| 社畜＋奧術 | 咖啡自動化 | 治療增快指揮官充能 |
| 機械＋暗影 | 幻影工廠 | 召喚攻擊同時疊毒 |
| 機械＋神話 | 天工神機 | 召喚附加神話爆發傷害 |

研究室用的角色是既有六種職業原型，並非正式角色池；敵人亦為測試模型，不代表六名新角色原畫或五名首領原畫已完成。

## 正式接入前的必要關卡

1. 原型的事件循環和效果都先做到 deterministic、無無限 loop、數據可重現，且不改動原始資料。
2. 多種敵人與至少八套明顯不同的構築，進行固定 seed 的多場模擬，避免實際只有一套最佳解。
3. 設計編隊頁、印記管理、融合查看、流派切換、裝備配置與研究報告，再正式引入六人隊伍的動畫、HP 與敵人群。
4. V19 存檔向新版的資料映射與復原方案必須另行驗證；所有薪資相關數字與遊戲強度完全獨立。
5. 正式切換前完成桌機和手機端的真實驗收，保留可回退原單人戰鬥的開關。

本輪僅 S1 原型與測試，不是完成版／可玩版。後續擴展應優先強化技能差異、羈絆平衡、真正六人戰鬥的角色動畫與介面，而非空增角色數量。
