日期：2026-11-09。**外型維持使用者確認的瘦、有短鬍渣、黑亂髮日本社畜大叔；此處僅重做受傷動作。**

## 已完成的美術（本輪對話產出於交付包，尚未提交 GitHub Binary）

- 單張原始 5 姿勢透明圖，實際拆成五張各 **512×512 RGBA PNG**，並提供 2560×512 無損 PNG 圖組、1920×384 高畫質 WebP 圖組、動態 GIF、棋盤格預覽及自包含離線 HTML 互動驗收。
- 五個獨立繪製姿勢：平常狀態、受擊縮起、痛得後仰、蹲下忍痛、疲憊恢復。手臂、頭、雙腳、公事包姿勢不同，**不是同一張圖片平移或旋轉**。
- 五幀透明 alpha 0–255；主角和手持公事包距離畫布邊界足夠；鞋底落點最大差異 8px（512px 座標）；相鄰影格畫素差異率 28.19%、34.48%、37.45%、27.84%。
- 390px 寬、DPR 2 的 Chromium 行動裝置模擬：離線自包含 HTML 成功解碼 1920×384 WebP、能播放影格，無 JavaScript 錯誤、無水平溢出。產出實際手機畫面截圖。**不等於真正 iPhone Safari／GitHub Pages 測試通過**。

## 已提交到 GitHub 的正式程式功能

- `v19/hurt-timing.mjs`：五姿勢時長 `[75,110,100,135,130]` 毫秒，總計 **550ms**。
- `v19/app.mjs`：只在 `?art=chibi-v2` 的可選 Q 版驗收模式中，依實際**主角被敵人反擊扣 HP**的結果播放受傷圖組。若是玩家擊敗敵人，則不觸發受傷。動畫與既有 7 姿勢攻擊播放銜接；×2 倍速也按遊戲速度計算，避免前一個攻擊影格在受傷後跳回。
- `v19/play.html`：新增「受傷動畫」圖片選擇器與獨立測試按鈕。從交付包選擇 `hurt_5pose_384.webp` 或 `hurt_5pose_512_lossless.png`，先驗證圖片大小和背景透明，再載入試玩。獨立「🩹 預覽受傷姿勢」按鈕不進入戰鬥邏輯、不扣血。圖片儲存在瀏覽器獨立的本機美術快取，不改寫薪資或玩家遊戲存檔。
- `v19/hurt-timing.test.mjs`：驗證 550ms 節奏、所有切片分界、512／384 尺寸許可、實際扣血才觸發；更新 `.github/workflows/v19-gameplay-ci.yml` 在程式變更時執行。
- `art/v19/candidates/characters/starter/manifest.json`：清楚標示 **美術候選／待玩家審查，尚未正式上線**。

### 如何實際驗收

1. 下載本輪的完整素材包 `salary_hero_chibi_hurt_v1_complete.zip`，直接開啟自包含 HTML 可離線看五種姿勢、背景換色及手動逐幀。
2. 手機上開啟 `https://hsia07.github.io/Salary-hero/v19/play.html?art=chibi-v2`。
3. 先照舊上傳七姿勢攻擊的高畫質 WebP（若瀏覽器已有快取可省略），再於「受傷動畫」欄位選擇 `hurt_5pose_384.webp`。
4. 關閉自動戰鬥後點「🩹 預覽受傷姿勢」，再手動打未死亡的敵人，確認受反擊才播放受傷動畫。
5. 比對腳底、頭髮毛邊、皮鞋／公事包位置及在 ×1／×2 倍速是否有不連續。
