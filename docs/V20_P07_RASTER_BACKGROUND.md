# 薪水勇者 V20 P0.7｜高精細繪景進入真正的遊戲引擎

日期：2026-11-11。

## 施工
- 新增兩張**真正的 WebP 點陣場景圖**（不是 CSS 生成的裝飾物，也不是把整頁 UI 畫成一張圖）：
  - `art/v20/runtime/backgrounds/town-painterly.webp`，960×560、約 51 KB
  - `art/v20/runtime/backgrounds/battle-painterly.webp`，720×620、約 46 KB
- 圖片取材自本專案重新生成的奇幻辦公室插畫，擷取無文字、無角色、無怪物、無按鈕的獨立景物，再以獨立程式重建木桌、鏡框、地板透視、光影、書架與漂浮微光。**不是整張手機畫面的死圖。**
- `v19/app.mjs` 正式戰鬥 `assetPaths.bg` 改為載入 WebP，怪物與 Q 版社畜主角、逐格動作和 HP 條仍然每幀獨立由 Canvas 畫出。練習模式仍使用自己的辦公室場景，不受影響。
- WebP 載入失敗時回退至既有 `corridor-v20-painterly.svg`；兩者都失敗則使用 `enchanted-office.svg`。`world.dataset.sceneArt` 標明實際分支。
- 主城 `v19/v20-art-live.css` 換成 `town-painterly.webp`，並減輕舊 SVG 金屬遮擋層、停用與新圖重複的向量書架。不能遮住遊戲可點擊的 DOM 元素。
- 正式戰鬥 WebP 不需大量濾鏡，每次載入時仍先預繪入快取 Canvas，之後保留主角、敵人、技能、損傷、環境光點的即時動畫。
- 因新材質自帶光影，將正式戰場的黑暗遮罩降低；練習模式保留原本顏色。

## 不可改動
- 不換主角（偏瘦、疲憊、略邋遢的 Q 版日本社畜大叔）。
- 不更動任何掉落機率、薪資計算、升級、戰鬥運算、存檔或裝備數據。
- 不把整張靜態示意畫當作介面；每個薪資和角色按鈕都必須是原本可操作 DOM。

## 驗收
- Node 測試驗證 WebP 標頭、實際檔案大小、背景路徑、原本 SVG 備援。
- Playwright 手機 390×844、375×667、320×568 證明新資產可以解碼，且主角/敵人動態正常、首頁不捲動、所有按鈕可以操作。
- 在真實 iPhone 上確認背景與你提供的參考圖是否足夠。**工程部署成功不能代表整體高精度原畫驗收完成。**
