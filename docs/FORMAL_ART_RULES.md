# 薪水勇者｜正式美術製作與驗收硬規則
版本：ART-RULES-1.0
適用：所有主角、SR/SSR 角色、敵人、BOSS、場景、裝備、武器、卡牌、技能特效、UI 美術與動畫。
狀態：**強制規則，不是參考建議。**

## 0. 每次生成前必讀（強制閘門）
在**每一次**新生成、重繪、修改、輸出或整合任何美術素材**之前**，開發者／AI 必須：
1. 重新開啟並完整閱讀本檔 `docs/FORMAL_ART_RULES.md`，不得只依賴記憶或上次摘要。
2. 檢查當次角色／場景的已核准設定、比例、配色、角色朝向、分層及動畫規格。
3. 逐條確認本檔第 1–7 節，才可撰寫生成提示詞、呼叫繪圖工具或編輯素材。
4. 生成完成後執行第 8 節的驗收；未通過者一律標記 `candidate`／`rejected`，**不得放入正式素材路徑**。
5. 每次提交新美術時，在 PR／commit 或驗收紀錄中註明「已重讀 ART-RULES-1.0」，列出驗收結果。沒有驗收紀錄視為未完成。
6. 若無法讀取本檔，**停止生成正式美術**，先恢復規則檔存取；不得猜測規則。

## 1. 去雜點
- 清除無設計用途的零碎像素、斑點、漂浮碎屑與孤立亮點。
- 不允許用隨機噪點假裝高級材質、金屬、皮革或背景細節。
- 保留有明確敘事目的且符合風格的磨損、污漬；需可辨識為刻意設計。

## 2. 去雜訊
- 禁止過度紋理、髒污、亂光影、混亂筆觸、AI 式碎裂高頻細節。
- 大色塊、乾淨的材質分區、統一光源與清楚明暗層次優先。
- 在手機實際顯示尺寸下，角色與技能必須能一眼辨認。

## 3. 去雜邊
- 透明 PNG/WebP 邊緣不得有白邊、黑邊、去背殘留、色溢、鋸齒、雙重輪廓與毛邊。
- 輪廓閉合、線條粗細一致；肢體與道具接縫自然。
- 檢查深色、淺色、透明棋盤格三種背景，避免只在單一背景上看似正常。

## 4. 去 AI 感
- 禁止五官錯位、手指錯誤、肢體連接不合理、衣物無法解釋的結構、裝飾物憑空消失、左右側不一致。
- 禁止亂碼文字、偽字、假介面符號。時鐘數字等重要資訊必須後製或精準驗證。
- 禁止不合理材質混合、光源相互矛盾、模糊遮掩結構錯誤。
- 不以「AI 味」作主觀唯一判準；必須逐項檢查可觀察的結構、細節與一致性。

## 5. 美術風格與設定一致性
- 方向：高品質日式 Q 版 RPG × 頹廢職場 × 奇幻異常；角色是精緻、有表情、有設計意圖的遊戲美術。
- 不得以 CSS 幾何拼接、簡單圖形、整張圖平移／晃動冒充正式角色美術或實質動作。
- 每名角色維持核准的臉、髮型、體態、衣裝、武器、配色與性格；前後／左右視角須能對得起來。
- 鐵時特例：瘦削、疲憊、微邋遢的男性守衛；紫黑金巨型直立矩形盾牌，**中央橫向數位電子鐘**；原始與中期為 `08:59`，僅最終和解覺醒變 `09:00`；SR 稀有度不變。
- 六人戰鬥畫面不得因特效與召喚物遮蔽隊伍；亡靈只在觸發時短暫出現，大招除外。

## 6. 正式分層素材
- 必須有可重用、透明背景的獨立部件：頭／頭髮前後、眼／表情、軀幹、上臂／前臂／手、腿、武器／盾牌、可選披風、技能 VFX。
- 明確定義每層的錨點、旋轉中心、前後遮擋、命名與輸出尺寸；保留可編輯來源。
- 不允許直接從合成概念圖粗裁角色、用一張扁平圖假裝分層。
- 各方向與動畫幀須維持比例、衣裝結構、盾牌時鐘內容一致。

## 7. 動畫規則
- 待機：有呼吸、眼神與自然微動；不得僅整張圖片上下漂浮。
- 移動：腳步／重心／衣擺／盾牌有實際對應動作。
- 攻擊：預備→出招→**武器或技能確實接觸目標**→命中→收招；不得隔空近戰。
- 受擊：清楚的姿態反應與短暫紅閃；不得只套模糊或粗糙位移。
- 格擋：盾牌移至受擊方向，有實際攔截與反作用。
- 大招：特效有層次、時序、遮擋規則，不讓整個畫面長時間被光效蓋住。
- 動作切換與回待機要順暢，不可斷幀、部件穿插或位置跳動。

## 8. 正式驗收清單
每份素材均須逐項 PASS：
- [ ] 已於本次生成前重新完整閱讀本檔。
- [ ] 符合已核准角色設定、比例、配色與正確朝向。
- [ ] 無雜點、無不必要噪訊。
- [ ] 無雜邊、透明邊緣乾淨。
- [ ] 無可見 AI 結構錯誤、亂碼或無意義裝飾。
- [ ] 可編輯分層來源與透明輸出齊備，錨點正確。
- [ ] 動畫各狀態完整，攻擊接觸與受擊紅閃經實際檢查。
- [ ] 深／淺背景、放大與手機原尺寸皆可讀。
- [ ] 實際遊戲畫面檢查無角色遮擋、層級打架、過度特效。
- [ ] 驗收紀錄可追溯；不合格項目已退回，不冒充正式完成。

## 9. 開發流程
`READ RULES → READ CHARACTER SPEC → GENERATE CANDIDATE → CLEANUP → LAYER/ANIMATE → QA → APPROVE → INTEGRATE`
- 任何階段失敗，退回上一步；禁止跳過 QA。
- 規格未確認時只能生成候選草稿，不可自稱正式版。
- 新角色／新副本沿用本檔；修改本檔需獨立提交，不能默默放寬標準。
